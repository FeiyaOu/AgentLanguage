🏠 Home.tsx Frontend

Landing page with a form where the user picks:

  • Mode — Exercise or Roleplay
  • Topic — e.g. "restaurant English"
  • Difficulty — beginner / intermediate / advanced
  • Persona (roleplay only) — friendly, grumpy waiter, lost tourist, strict teacher, or custom

On submit it either calls generatePractice() API or navigates to /roleplay with state.

📝 Practice.tsx Frontend

Renders exercises received via React Router state. Supports:

  • Multiple choice — radio button cards
  • Fill-in-the-blank — text input
  • Roleplay-style — text input

Submits scoreAnswers(exercises, answers) then navigates to /feedback.

📊 Feedback.tsx Frontend

Rich feedback page showing:

  • Overall score percentage + emoji
  • Per-question breakdown (correct/incorrect, feedback, answers)
  • Weak areas tags
  • AI recommendations
  • Ask AI Tutor modal per question
  • Practice Weak Areas button → regenerates exercises focused on weaknesses

🎭 Roleplay.tsx Frontend

Two-phase interactive chat:

  1. Briefing screen — shows scene, partner, mission, and pro tip
  2. Chat interface — alternating user/persona messages with a coach feedback modal every 3 turns

Uses startRoleplay(), sendRoleplayMessage(), and endRoleplay() APIs.

Page Routing & Navigation

All page-to-page data is passed via React Router location.state — there is no global store (Redux, Context, etc.). Each page guards itself: if the expected state is missing, it redirects back to /.

Backend – FastAPI Server

backend/main.py Backend

A single-file FastAPI application (~496 lines) that:

  • Loads OPENAI_API_KEY from .env
  • Configures CORS for Vite dev ports (5173-5175, 3000)
  • Instantiates a single LanguageLearningAgent
  • Defines Pydantic request/response models
  • Exposes 7 REST endpoints (see API section)
  • Stores roleplay sessions in-memory (roleplay_sessions dict)

Scoring Logic (Hybrid)

The /api/score-answers endpoint uses a hybrid approach:

  • Deterministic for multiple_choice and fill_in_the_blank — normalized string comparison
  • AI-evaluated for open-ended types like roleplay — delegates to ScoreAndAnalyzeTool
  • Both are merged into a unified detailed_scores response

backend/agent/agent.py AI Agent

LanguageLearningAgent class

This is the core reasoning loop. Key design decisions:

  • No framework dependencies — just openai SDK + regex parsing
  • Structured output format — the LLM is instructed to output THOUGHT:, TOOL:, TOOL_INPUT:, or RESPONSE: blocks
  • Tool dispatch — tools are registered in a dict; agent calls them by name
  • Conversation memory — full chat history is maintained and passed to every LLM call
  • Max 5 iterations — prevents infinite tool-calling loops
  • Robust JSON extraction — handles fenced code blocks, searches for first [/{

backend/agent/prompts.py AI Agent

System Prompt

Defines the agent's personality and expected output format. Instructs the model to:

THOUGHT: [reasoning]
TOOL: [tool_name]
TOOL_INPUT: {"topic": "...", "difficulty": "..."}

— or —

THOUGHT: [reasoning]
RESPONSE: [message to user]

Roleplay Feature – Deep Dive

Persona System

Coach Feedback System

Every 3rd user turn (turn_count % 3 == 0), instead of a persona reply, the system generates a coach analysis:

  • Politeness Score (0-100) — how appropriate the language is
  • Grammar Notes — specific corrections with examples
  • Vocabulary Suggestions — better word choices / useful phrases
  • Encouragement — positive feedback
  • Persona Resume — the character continues the conversation naturally after feedback

# → Runs on http://localhost:5173

4. Open in browser

open http://localhost:5173

Key Design Decisions

🔧 No LangChain

The agent is built from scratch with just the OpenAI SDK. The reasoning loop is ~60 lines of Python using regex parsing. This makes it fully transparent and easy to debug.

🔀 Hybrid Scoring

Multiple choice and fill-in-the-blank use deterministic string matching (normalized). Open-ended answers use AI evaluation. Both are merged into a unified response.

🗂️ State via Router

No Redux/Zustand/Context. All inter-page data flows through navigate(path, { state }). Simple, but means you can't deep-link to /practice directly.

🎭 In-memory Sessions

Roleplay sessions are stored in a Python dict. This means they don't survive server restarts — fine for a dev/demo app, but would need a DB for production.
