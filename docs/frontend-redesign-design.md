# 前端改版设计文档：设计规范、动效、导航与登录

> 状态：草案 · 2026-10-31
> 说明：第 1–9 节为完整方案；**第 10 节为已确定的简化版（MVP），当前按此执行**。

---

## 1. 背景与目标

现有前端被反馈"不够好"。本次改版有两个目标：

1. **产品层面**：页面更规范，有清晰的导航；支持登录/登出；页面过渡和加载反馈更专业、更有设计感。
2. **能力展示层面**：项目要能作为以下能力的落地证据：

| 能力要求 | 需要体现的证据 | 本项目中的落地点 |
|---|---|---|
| 统一颜色、字号、间距、主题 | 一套 design tokens，而非散落的 `orange-500` | CSS 变量 + Tailwind theme；深色模式只在一处切换 |
| 跨项目复用组件 | 组件是独立一层，有文档，可抽出复用 | `ui/` 组件目录（不依赖业务代码）+ Storybook |
| 组件状态与交互规范 | 每个组件定义 default / hover / active / focus / disabled / loading / error | cva 管理变体；Storybook 列出全部状态 |
| CSS 动画、页面过渡 | 代码实现的动效，且有规范 | motion tokens；路由过渡 |
| 加载反馈、Lottie | 按等待时长分级反馈；Lottie 由代码控制 | 骨架屏、分阶段进度、打字指示、dotLottie |

> 注意：After Effects 制作素材不算 Web 动效经验。使用现成 Lottie 素材时如实说明来源，重点在代码侧：播放控制、分段触发、主题换色、懒加载与离屏暂停。

## 2. 现状问题

**视觉**
- 首页是通用"AI 产品落地页"模板：渐变大标题、模糊光斑、发光卡片、闪烁徽章，缺乏学习产品的辨识度。
- 品牌名不统一：README/图标是 *TalkTutor*，页面标题和页脚是 *AgentLanguage*。
- Tailwind 配置了 Inter 字体但从未加载，实际显示系统字体。
- 橙色用于一切，没有视觉层级。

**体验**
- 没有导航，只有右上角的"回首页"按钮。
- 状态全靠路由 `location.state` 传递：刷新 `/practice` 会跳回首页；刷新 `/roleplay` 很可能直接报错（[Roleplay.tsx:25](../frontend/src/pages/Roleplay.tsx) 解构了 `null`）。
- 7 处使用 `alert()` 做校验和错误提示。
- 加载只有转圈；没有页面过渡。
- 不保存任何历史。

**代码**
- 页面组件 400–700 行，Tailwind 长类名大量重复，几乎没有共享组件。
- 深色模式逐个手写，约 170 处 `dark:` 类名。
- 无障碍语义缺失（选项按钮无 radio 语义，弹窗未处理焦点）。
- `axios` 被放在 devDependencies；`api.ts` 中响应映射代码重复。

## 3. 方案对比

| | 方案 A：轻量原生 | **方案 B：主流组件体系（推荐）** | 方案 C：完整设计系统 |
|---|---|---|---|
| 思路 | 少用库，体现 CSS 基本功 | 业界主流组合，做成完整 app | B + 组件库真正抽出、可发布 |
| 组件 | 自己手写 | shadcn/ui + Radix + cva | 同 B，抽到 `packages/ui` |
| 过渡 | View Transitions API | Motion `AnimatePresence` / `layoutId`（可结合 View Transitions） | 同 B |
| 文档 | 无 | Storybook | Storybook 公开部署 + Chromatic 视觉回归 |
| Tokens | CSS 变量 | CSS 变量 + Tailwind theme | Style Dictionary 单一来源生成（可接 Figma Tokens Studio） |
| 登录 | mock | Supabase Auth（自绘 UI） | 同 B |
| 特色 | 依赖少 | 覆盖全部要求 | Rive 状态机角色头像 |
| 工期 | 约 1 周 | 约 2–3 周 | 4 周以上 |
| 不足 | "跨项目复用"说服力弱；无障碍需自理 | 比 A 多 1–2 周 | 工作量大 |

**结论**：以方案 B 为主，吸收方案 C 的两点：
1. 定义 **motion tokens**，Storybook 中加一页"动效规范"。
2. `ui/` 组件放在独立目录、不依赖业务代码，结构上可抽出复用。

## 4. 设计规范（Design Tokens 与组件）

### 4.1 Tokens

所有视觉值以 CSS 变量定义，Tailwind 引用变量；深色模式只覆盖变量值。

| 类别 | 内容 |
|---|---|
| 颜色 | 语义化命名：`--surface`、`--surface-raised`、`--text`、`--text-muted`、`--border`、`--accent`、`--success`、`--warning`、`--danger`。品牌色只有一个强调色，其余为中性色 |
| 字号 | 固定阶梯（如 12 / 14 / 16 / 20 / 24 / 32 / 48），配套行高 |
| 间距 | 4px 基准阶梯 |
| 圆角、阴影 | 各 3–4 档 |
| 动效 | 见第 5.1 节 |

字体：`@fontsource/inter`；如目标用户为中文用户，补充思源黑体或 HarmonyOS Sans。

### 4.2 组件

首批基础组件：Button、Card、Input、Chip、Modal/Dialog、Drawer、Toast、Skeleton、Avatar、Progress、EmptyState。

- 行为层（焦点管理、键盘交互、ARIA）交给 **Radix UI**；视觉层与状态规范自定义。
- 用 **class-variance-authority (cva)** 定义 `variant × size × state`。
- 每个组件必须覆盖：default / hover / active / focus-visible / disabled / loading / error（适用时）。
- Storybook 每个组件一页，列出全部状态；另设 tokens 页、动效规范页。

## 5. 动效规范与加载反馈

### 5.1 Motion tokens

| Token | 值（初定） | 用途 |
|---|---|---|
| `--duration-fast` | 150ms | hover、按下、小元素状态变化 |
| `--duration-base` | 250ms | 弹窗、卡片进入、Toast |
| `--duration-slow` | 400ms | 页面过渡、共享元素过渡 |
| `--ease-standard` | 标准缓动 | 大多数过渡 |
| `--ease-emphasized` | 强调缓动 | 进入画面的重要元素 |

### 5.2 页面过渡
- 统一：淡入 + 轻微位移。
- 练习页 → 结果页：共享元素过渡（`layoutId`）。

### 5.3 加载反馈分级

| 等待时长 | 反馈方式 |
|---|---|
| < 300ms | 不显示（避免闪烁） |
| 300ms – 1s | 轻量指示（按钮内 spinner、进度条） |
| > 1s | 骨架屏或分阶段进度 |
| > 3s | 明确告知"正在做什么" |

### 5.4 场景设计

| 场景 | 现状 | 改为 |
|---|---|---|
| 生成练习题（3–8 秒） | 转圈 | 分阶段文案（"理解主题…" → "出题中…" → "检查答案…"）+ Lottie 小插画，最后由题卡骨架屏过渡到真实内容 |
| 推荐对话角色 | "Summoning actors..." + 转圈 | 4 张卡片骨架，数据到达后逐张错开翻入 |
| 角色回复 | 等整条回复 | 打字指示（三个点）；后续可改流式逐字 |
| 提交评分 | 按钮变灰 | 按钮内 loading → 完成变对勾；结果页分数从 0 计数 + 环形进度 |
| 出错 | `alert()` | Sonner toast，或带重试按钮的行内错误卡片 |
| 高分 | 无 | canvas-confetti（克制使用） |

### 5.5 无障碍
支持 `prefers-reduced-motion`：开启时关闭位移与缩放，只保留淡入淡出；Lottie 停在静态帧。

## 6. 信息架构与导航

**页面结构**：首页 / 练习 / 角色扮演 / 学习记录 / 个人中心，外加独立 `/login` 页。

**App Shell**
- 桌面端：顶部导航（或左侧栏）。
- 移动端：底部 Tab 栏。
- 右上角：游客显示"登录"按钮；已登录显示头像下拉菜单（学习记录、设置、退出登录）。

**路由与状态**
- 可分享、需刷新安全的状态放 URL 参数；进行中的会话放轻量 store（如 Zustand）或 sessionStorage。
- 接口调用统一用 TanStack Query（加载、错误、重试一致）。

## 7. 登录设计：游客可用，登录保存

### 7.1 原则
- **不登录也能完整使用**练习和角色扮演，但不保存结果。
- **登录后**保存历史，可回看旧题。
- 采用"先体验、后注册"：用户有了想保存的东西时再引导登录，不在入口拦截。

### 7.2 登录引导时机
- **结果页**：卡片"登录后保存这次成绩，以后可以回看错题"。
- **角色扮演结束**：同样提示一次。
- **学习记录 Tab**：对游客可见，显示设计过的空状态（Lottie 插画 + 说明 + 登录按钮）。
- 登录形式：弹窗或侧边抽屉，登录后**留在当前页面**；另保留 `/login` 页供直接访问。

### 7.3 认领当前成绩（关键）
用户做完题点"登录保存"，登录后成绩不能丢失：
1. 游客模式下，**仅当前这一次**结果暂存在浏览器本地。
2. 登录成功后自动认领到账号，toast 提示"已保存到你的学习记录"。
3. 暂存数据认领后即清除；游客不积累历史。

### 7.4 登录前后界面状态

| 位置 | 游客 | 已登录 |
|---|---|---|
| 导航右上角 | "登录"按钮 | 头像 + 下拉菜单（含退出登录） |
| 结果页 | "登录保存"卡片 | "已保存"标记 + "查看历史"入口 |
| 学习记录 | 空状态 + 登录引导 | 历史列表 |
| 首页 | 普通入口 | 增加"继续上次""复习错题" |

**会话检查中**：刷新时确认登录状态约需数百毫秒，此期间右上角显示头像尺寸的骨架占位，避免"登录"按钮闪现后再变头像。

**退出登录**：回到游客状态，清除本地缓存的个人数据，toast 提示"已退出"。

### 7.5 保存内容

| 内容 | 字段 | 优先级 |
|---|---|---|
| 练习记录 | 主题、难度、题目、用户答案、正确答案、AI 反馈、得分、时间 | P0 |
| 错题本 | 从练习记录筛出错题，支持重新作答 | P0 |
| 角色扮演记录 | 完整对话、教练反馈、目标是否达成 | P1 |
| 薄弱点汇总 | 聚合多次 `weak_areas`，首页推荐针对性练习 | P1 |

### 7.6 额度分级
现有按 IP 限流。有账号后：游客额度较低（如每天 3 次练习），登录用户较高。既控制成本，也给出登录理由。

### 7.7 技术选型
- **Supabase**：同时提供 Auth 与 Postgres；开启行级安全（RLS）后前端可直接读写"仅属于自己"的数据。
- 登录 UI 自绘（不用 Clerk 预制 UI，以便展示设计能力）。
- 若目标用户在国内，Supabase 访问可能较慢，备选 **Logto**（开源可自建）或 **Authing**。
- 后端需补：校验登录状态、"保存记录"与"查询历史"接口；可并入后端重构一起完成。

### 7.8 备选方案（未采用）
"不登录也保存在本机，登录后云端同步"：游客也能看历史，但需要处理本地数据与账号合并，复杂度更高。当前采用"不登录不保存 + 认领当前成绩"。

## 9. 实施阶段

1. **修复明显问题**（约 1 天）：刷新崩溃、`alert()`、品牌名、字体加载。
2. **基础设施**：tokens、基础组件、Storybook、TanStack Query、刷新安全的状态管理。
3. **导航与 App Shell**：顶部导航 / 底部 Tab、头像菜单。
4. **动效与加载**：motion tokens、页面过渡、第 5.4 节各场景、reduced motion。
5. **登录**：Supabase Auth、登录弹窗与页面、会话骨架态、退出登录。
6. **保存与历史**：认领当前成绩、学习记录列表、错题本。
7. **视觉识别**：在组件体系就绪后统一调整视觉风格。

**面试展示材料**：改版前后对比录屏（30 秒）、Storybook 链接（tokens 页、Button 全状态、动效规范页）、设计决策讲解（骨架屏 vs 转圈、300ms 阈值、reduced motion）。

## 10. 简化版（MVP）

> 2026-10-31 确定。背景：接下来是设计团队面试，**只改前端，后端不动**，目标是让前端看起来更专业。

### 10.1 已确定的决策

| 项 | 决定 |
|---|---|
| 范围 | 仅前端；不新增后端接口 |
| 风格 | **方向 B（克制专业）+ C 的温度**（角色头像/插画、恰当的动效） |
| 界面语言 | 英文 |
| 品牌名 | **AgentLanguage**（统一页面标题、页脚、Logo；README 中的 TalkTutor 后续同步） |
| Storybook | 暂不做；组件仍放在独立 `ui/` 目录，保持可抽出。以 `/design-system` 页面作为在线样式指南替代（展示全部 tokens 与组件状态） |
| 登录 | **模拟登录**：登录状态与练习记录存于浏览器本地，学习记录页显示真实数据；面试时说明"UI 与状态流完整，后端未接入" |
| 即时判题 | 题目数据自带正确答案，前端即时判对错；AI 详细反馈仍在结果页统一获取（沿用现有接口） |

### 10.2 风格要点
- **删除**：背景光斑、发光边框、渐变文字、闪烁徽章、多层毛玻璃、永不停止的扫光等循环动画。
- 暖中性底色 + **唯一强调色**；以排版和留白建立层级。
- 卡片用细描边，阴影只用于浮层。
- emoji 不作界面图标，统一一套图标；emoji 只用于角色。AI 推荐的角色 emoji 要带进对话头像。
- 难度标签改为中性色 + 1/2/3 个点。

### 10.3 Tokens（三层）
- **基础层**：原始色板，组件不直接引用。
- **语义层**：`accent`、`surface`、`surface-raised`、`text`、`text-muted`、`border`、`success`、`danger`（及其浅色变体）；**深色模式只替换此层**。
- **组件层**：按需少量添加。
- 字号：display / title / heading / body / label / caption 六级，含行高与字重。
- 间距 4px 基准；圆角规则：控件 md、卡片 lg、标签/头像 full；层级 0 / 1（描边）/ 2（浮层阴影）。
- 动效：fast 150ms / base 250ms / slow 400ms；standard / emphasized 缓动；交互用 spring。
- 修复现有深色模式遗漏：练习页标题、错误卡片、角色扮演加载文字。

### 10.4 导航
- **全局导航**（首页、学习记录、个人中心）：Logo｜Practice · Roleplay · History｜主题切换 + Log in / 头像菜单（History、Settings、Log out）。当前页指示器滑动（`layoutId`）。
- **专注模式**（做题、对话中）：隐藏全局导航，只保留退出（带确认）、标题、进度。
- 移动端：全局导航改为底部 Tab 栏。
- 移除现有右上角浮动按钮（会遮挡角色扮演页的 End Session）。
- 会话确认期间头像位置显示骨架占位。

路由（第 2 步实现）：

| 路径 | 页面 | 布局 |
|---|---|---|
| `/` | 首页 | 全局导航 |
| `/practice` | 练习设置 | 全局导航 |
| `/practice/session` | 做题 | 专注模式 |
| `/practice/results` | 结果 | 全局导航 |
| `/roleplay` | 角色扮演设置 | 全局导航 |
| `/roleplay/session` | 对话 | 专注模式 |
| `/history` | 学习记录 | 全局导航 |
| `/design-system` | 样式指南（按需加载） | 全局导航 |

首页与设置页的推荐主题通过 `?topic=` 预填。

### 10.5 页面构图
- **首页**：应用式首页；问候语 + 两个等高入口卡片，各附可点选的推荐主题；删除功能介绍条。
- **练习页**：一次一题；顶部分段进度、中间题卡、底部固定 Check 按钮；即时对错 → Next。
- **结果页**：分数环 + 与分数匹配的三档文案 → 薄弱点与建议 → 逐题回顾（默认折叠，错题展开，颜色仅用于左边线和图标）→ 主按钮"针对薄弱点再练"、次按钮"换个主题"。
- **角色扮演**：三层头部压缩为一行（头像与名字｜细进度条｜剩余回合 + 菜单）；目标收进可展开条或抽屉；对话区不少于 75% 视口高度。
- **学习记录**：游客显示空状态 + 登录引导；已登录显示本地记录列表。
- 内容宽度：阅读型页面约 720px，首页约 1080px。

### 10.6 动效与加载
- 原则：动效只用于**反馈、引导、连续性**；循环动画仅限加载。
- 场景：路由淡入 + 8px 位移（仅进入动画，无退出等待）；进入专注模式时页面淡入、顶栏下滑、底部操作栏上滑（容器不加 transform，避免影响 fixed 元素）；选项弹性选中；答对对勾沿路径绘制、答错轻微抖动；换题水平滑动；排序题词块飞入句子区（`layout`）；结果页分数计数 + 画环；对话气泡从说话方一侧进入；目标达成播放 Lottie / 彩带；按钮按下 0.98、加载保持宽度并在完成后变对勾。
- 加载统一三种：骨架屏（角色卡片、题卡）、分阶段文案 + Lottie（生成练习题）、打字指示（对话）。
- Lottie 仅 2–3 处：生成练习题、学习记录空状态、任务完成；代码控制播放并跟随主题换色。
  - 实现（第 6 步）：`lottie-react` v3 的 `LottieLight`，按需加载（独立 chunk 约 53KB gzip，主包不受影响）。
  - 动画文件（`src/assets/lottie/*.json`）由脚本生成，非 After Effects 导出；填充/描边以 token 命名（`accent`、`surface`…），运行时读取 CSS 变量替换颜色，主题切换时重新着色。
  - `ThemedLottie`：离屏暂停（IntersectionObserver）、`segment` 只播放片段、减少动态效果时直接停在指定帧。
- 所有 `alert()` 替换为 Sonner toast 或行内错误。
- 支持 `prefers-reduced-motion`：位移、缩放、抖动改为淡入淡出。
